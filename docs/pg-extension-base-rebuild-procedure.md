# Fresh rebuild procedure for the combined prototype

> Historical prototype record. Commands and source paths below refer to the
> [preserved implementation](https://github.com/proddata/lake_replication/tree/7ef18381810075dddd26137ee959770591b95863/experiments/base_workers) before cleanup.
> Current lifecycle tests live in `tests/lifecycle`; retained admission helpers
> are described in [experiments/admission](../experiments/admission/README.md).

Status: tested as a disposable rehearsal on the combined origin-check/retry
prototype. This is not a production package upgrade, an in-place rebind or a
writable takeover of existing Iceberg objects. The shipping release does not
include the prototype's origin checks.

## Supported scope

Create a new destination database from `template0`, with a fresh subscription,
source slot and empty storage prefix. Perform a new consistent initial copy,
then stream from that subscription's own checkpoints. Retain the original target
and its source slot during the rollback window. Leave inherited configurations
fenced and unchanged.

| Resource | Rebuild allocation |
| --- | --- |
| Destination database identity | New OID; new configuration records its actual cluster/OID/name. |
| Source connection and publication | Explicitly reviewed for the new subscription; credentials supplied through the normal native SQL/credential-file path. |
| Source slot | New, previously absent name; never reuse the inherited slot. |
| Iceberg table and storage | Newly created table under an explicit empty, separate location prefix. |
| Journal, checkpoints, initial-copy state | Start empty; generated by the new subscription. |
| Original target and slot | Retained for rollback; candidate cleanup cannot delete them. |
| Inherited clone/restore metadata | Remains stopped; do not rewrite its origin fields or copy its checkpoints. |

The source must permit a new snapshot and logical slot, and the target must have
the qualified pg_lake dependencies, credentials and required worker capacity.
The tested topology uses Docker init as the orphan reaper. Other process-owner
topologies remain unqualified.

## Procedure and review points

1. Record the original database identity, subscription/publication/slot, current
   checkpoints, Iceberg table locations and metadata snapshot locations. Disable
   its subscription and confirm its wrapper exits and its source slot becomes
   inactive. Retain the slot and its required WAL for the rollback window.
2. Select a fresh database name, subscription/slot name and storage prefix.
   Confirm the slot does not exist and the prefix is empty. Create the database
   from `template0`, install the combined prototype and its dependencies, and
   set an explicit `pg_lake_iceberg.default_location_prefix`. Confirm there are
   no subscriptions, launch rows, checkpoints, initial-copy records or existing
   destination tables. These are preconditions, not permission to clear an
   existing target.
3. Create a new native Iceberg subscription using the reviewed source connection
   and publication. Let it create its own source slot and perform initial copy.
   Verify its origin check, actual Iceberg location and slot name. Check that
   neither new location is inside the original location nor vice versa.
4. Validate source/current destination rows, keys and payloads at an agreed
   source write barrier or consistent validation snapshot. Verify subsequent
   inserts, updates and deletes, durable checkpoints and restart recovery.
   Confirm the paused original's rows, metadata snapshot and checkpoint have
   not changed. Confirm inherited configurations remain fenced.
5. Switch consumer connections only after application-specific consistency and
   cutover checks. The rehearsal does not change consumer/application traffic;
   it tests the replication state needed for a switch. Concurrent production
   writes need a separately designed validation barrier and routing procedure.
6. For replication rollback, disable and drain the candidate, retain its slot
   and objects, then enable the original subscription using its own retained
   slot. Wait for it to catch up and validate rows before switching consumers
   back. This requires usable retained WAL and an unchanged source identity.
   Lost/invalidated WAL, source replacement or a fatal source error require a
   separately validated recovery; ENABLE does not clear those errors.
7. Once a target is abandoned and its actual origin/ownership still validates,
   DROP its subscription through the native interface and verify that only its
   own source slot disappears. Retaining an Iceberg table and its objects is
   expected: native DROP SUBSCRIPTION does not remove the table in this path.
   Apply a separately reviewed data-retention/garbage-collection policy later.
   Do not run source cleanup through an inherited clone's subscription.

The relevant SQL shape, with deployment-specific values reviewed first, is:

```sql
-- Source: confirm fresh_rebuild_sub is absent from pg_replication_slots.
-- Target administrative database:
CREATE DATABASE fresh_target TEMPLATE template0;
ALTER DATABASE fresh_target SET pg_lake_iceberg.default_location_prefix =
  's3://<bucket>/<new-empty-prefix>';

-- In fresh_target, with the combined experimental package installed:
CREATE EXTENSION pg_lake CASCADE;
CREATE EXTENSION dblink;
CREATE EXTENSION lake_replication;
-- Confirm empty extension state and storage before proceeding.
CREATE SUBSCRIPTION fresh_rebuild_sub
  CONNECTION '<reviewed-source-conninfo>' PUBLICATION reviewed_publication
  WITH (lake_target='iceberg',
        lake_credential_file='/<reviewed-credential-file>');
-- The default source slot name is fresh_rebuild_sub.
```

The executable [rehearsal](https://github.com/proddata/lake_replication/tree/7ef18381810075dddd26137ee959770591b95863/experiments/base_workers/rebuild.py) enforces these
allocation checks and verifies results on private fixtures. The SQL outline is
not a generic rebuild command for an arbitrary existing database. There is no
implemented in-place `rebind` API.

## Rehearsal results

The [retained run](evidence/2026-10-19-base-fresh-rebuild-results.json) passed
**69/69 assertions** on Linux arm64/PostgreSQL 18.6 using the exact
identity-qualified image. It exercises real writable Iceberg tables, not
placeholder relations or metadata-only restoration.

| Check | Observed result |
| --- | --- |
| Candidate allocation | Empty database state, absent source slot and empty storage prefix verified before creation. |
| Current-state rebuild | Fresh initial copy includes intervening updates/deletes; one initial copy and a new slot/checkpoint. |
| Original isolation | Paused rows, checkpoint and Iceberg metadata path stay unchanged while candidate copies and streams. |
| Inherited clone | Origin fence and source cleanup rejection remain in effect; launch configuration/checkpoint stay unchanged. |
| Restart | Candidate resumes streaming; original and inherited clone remain stopped; no repeated copy. |
| Replication rollback | Original catches up via its retained slot, including mixed updates/deletes, without another copy; candidate stays frozen while paused. |
| Candidate catch-up and removal | Candidate catches up again, then native DROP removes only its slot; its table is retained and the original still streams. |

The parent image, archive metadata, harness/runtime fingerprints and log hashes
are retained in the JSON. Exact harness and logs remain under
`.qualification/qualification_20261019_110507_rebuild/`. An initial harness query
used the catalog view's table-name column as regclass; correcting it to the
view's catalog/schema/name fields produced the retained completed run. No
runtime source changes were needed for this procedure.

`make check` passed, source/evidence hashes were verified, and all private
rehearsal containers and volumes were removed. Production worker, migration and
extension sources still match the archived test source. New work remains local,
uncommitted and unpushed. This short same-cluster run does not qualify source
WAL loss, long rollback retention, application routing, cross-cluster restore,
physical-copy exclusivity, in-place rebind or production packaging.

## Why existing-object rebind is still blocked

The full dump test fails when it recreates a writable Iceberg table at an
existing non-empty location. A metadata-only restore required a placeholder
relation and did not restore the Iceberg data. Neither route establishes a
writable binding to existing objects.

Before supporting rebind/takeover, qualify the existing table's catalog, storage
and snapshot identity; prove old writers are drained or fenced; validate source
slot and checkpoint continuity; check ownership before publication and cleanup;
and specify rollback from each failed transition. Physical copies can preserve
cluster identifier, database OID and name, so the origin tuple alone cannot
prove exclusivity. A destination-scoped lease or an explicit exclusive-writer
procedure is still needed. Do not replace these checks with direct updates to
origin columns, SQL state or checkpoint LSNs.
